# 日報自動生成システム（Google Apps Script）

Google カレンダーの予定から日報を生成し、スプレッドシートの「日報」シートへ下書きとして
書き出す GAS プロジェクトです。Chatwork への送信は、シートのボタンを押したときだけ行います。

**日報用スプレッドシートの［拡張機能］→［Apps Script］に紐づけて使います。**
単独の Apps Script プロジェクトでは、シートへの書き出しとボタンが動きません。

- 昼（12:55 頃）: 当日 AM を「業務報告」、当日 PM を「業務予定」として作成
- 夜（18:25 頃）: スプレッドシートの「日報」タブをそのまま本文として読み込み
- 土日祝は作成しない（トリガーは止めない）
- LLM は使用しない。カレンダーのタイトルをそのまま整形するだけ

## 自動実行から Chatwork へは送信しません

「日報を作る」と「Chatwork へ送る」を完全に分けています。

```
Google カレンダー
      ↓
     GAS（12:55 / 18:25 のトリガー）
      ↓
   日報を生成
      ↓
「日報」シートに 1 行追加      ← ここまでが自動。Chatwork API は呼ばれない
      ↓
   本文セルで所感を書き足す（そのままでもよい）
      ↓
   シートのボタン → 確認ダイアログ →［はい］
      ↓
Chatwork 本番ルーム（122205264）／ 行の状態が「送信済み」に変わる
```

| | 自動実行（トリガー） | 手動実行 |
|---|---|---|
| 日報の生成 | する | する（下書きが無ければ） |
| 下書きの保存 | する | する |
| シートへの書き出し | する | する |
| **Chatwork への送信** | **しない** | ボタンを押して確認ダイアログで［はい］を選んだときだけ |

> 送信するのは**シートに書かれている本文**です。セル上で所感を書き足せば、その内容が送られます。

## 0. Apps Script へ貼る 1 本のファイル

実運用では、ファイルを分けずに 1 枚貼っている。まとめたものはここにある。

```
gas/daily-report/bundle/日報自動生成.gs
```

これは自動生成なので直さないこと。直すのは分かれている方で、そのあと作り直す。

```
npm run bundle:gas     # まとめ直す
npm run check:bundle   # 最新かどうかを確かめる（npm run verify にも入っている）
```

分かれている方だけ直して貼り忘れると、Apps Script 側だけ古いまま動き続ける。
実際にそれで、直したはずの不具合が再発した。`npm run verify` で気づけるようにしてある。

貼り替えたあとは、［デプロイを管理］→ 編集 → バージョン「新バージョン」で更新する。
保存しただけでは、ウェブアプリ（＝プラットフォームの日報ページ）は古いコードのまま動く。

### 日報のフォーマット

昼:

```
---業務報告---
AM
■予定1
■予定2
 
---業務予定---
PM
■予定3
■予定4
```

（`---業務予定---` の直前は半角スペース 1 つだけの行です）

夜:

夜の日報は**スプレッドシートの「日報」タブがそのまま本文**になる（§4-2）。
挨拶も日付も進捗状況も業務報告も、すべてシート側で組まれている。
GAS はそれを読むだけで、文面を作らない。

```
お疲れ様です。山本です。
2026年9月12日(土)の日報をお送りいたします。

＜進捗状況＞　　実績/目標
★リード売上    69.4万円　/ 　60万円　進捗率115.%（オンスケは28万円）
…
---業務報告---
PM
■運営MTG
---所感---
```

昼と夜で作り方が違う理由は、以前は夜も GAS 側で組み立てていたが、シート側にも
同じ形があったため、進捗状況を足したときに見出しが二重になったから。
同じ文面を二か所に置かない。

- 昼の「所感」は入りません（夜のみ・シート側にある）。
- 昼は本文が**そのまま Chatwork へ貼れるもの**だけです。「【昼用】」のような見出しは入りません。
- 昼は予定が無い時間帯でも `AM` / `PM` の見出しを残し、「予定なし」等は入れません。
- カレンダーのタイトルに既に `■` が付いている場合、二重には付きません。

## 3. Google Apps Script 側で必要な設定

1. 会社の Google アカウント（`yamamoto@aismiley.co.jp`）でログインする。
2. 新しい Apps Script プロジェクトを作成する。
3. `*.gs` の各ファイルを同名で作成し、内容を貼り付ける。
4. ［プロジェクトの設定］→［全般設定］で **タイムゾーンを `Asia/Tokyo`** にする。
   （ずれていると実行時にエラーになります）
5. `appsscript.json` を反映する場合は、［プロジェクトの設定］で
   「`appsscript.json` マニフェスト ファイルをエディタで表示する」を有効にしてから貼り付ける。

> clasp を使う場合は、このディレクトリをそのまま `clasp push` の対象にできます
> （`.clasp.json` は各自のローカルで作成してください。リポジトリには含めません）。

## 4. Script Properties へ設定する値

［プロジェクトの設定］→［スクリプト プロパティ］で設定します。

| キー | 必須 | 内容 |
|---|---|---|
| `CHATWORK_API_TOKEN` | 必須 | Chatwork の API トークン |
| `CHATWORK_ROOM_ID` | 必須 | 本番の投稿先ルーム ID（`122205264`）。手動送信のときだけ使われます |
| `HOLIDAY_CALENDAR_ID` | 任意 | 祝日カレンダー ID。未設定なら `ja.japanese#holiday@group.v.calendar.google.com`（→ §12） |
| `TARGET_CALENDAR_ID` | 任意 | 予定を取得するカレンダー ID。未設定なら実行アカウントのデフォルトカレンダー |

**API トークンはコード・README・Git に絶対に書かないでください。** 設定するのは Script Properties だけです。

なお、同じ Script Properties へ以下のキーも自動で追加されます。手で設定する必要はありません。

| キー | 内容 |
|---|---|
| `20260911_day` / `20260911_night` | 本番ルームへの送信済みフラグ（値は `sent`）。消すとその日の日報を再送信できます |
| `draft_20260911_day` / `draft_20260911_night` | 日報の下書きの控え（下記の形式の JSON）。表示・編集はシート側で行います |

### 「日報」シートの列

下書きは初回実行時に作られる「日報」シートへ、新しいものが上に来るよう 1 行ずつ書き出します。

| 列 | 内容 |
|---|---|
| 日付 | `2026-09-11` |
| 種別 | `昼` / `夜` |
| 状態 | `未送信` / `送信済み` |
| 日報本文 | ここを直接書き換えられます。送信時はこの内容が送られます |
| 生成日時 | 下書きを作った時刻 |
| 送信日時 | Chatwork へ送った時刻 |

送信済みの行は、下書きを作り直しても書き換わりません。

### 下書きの控え（Script Properties）

シートが使えないときの保険として、同じ内容を次の形でも保存しています。

```json
{
  "reportDate": "2026-09-11",
  "reportType": "day",
  "body": "---業務報告---\nAM\n■朝礼\n \n---業務予定---\nPM\n■昼礼",
  "status": "draft",
  "generatedAt": "2026-09-11T12:55:03+09:00",
  "sentAt": "2026-09-11T13:01:12+09:00"
}
```

| 項目 | 内容 |
|---|---|
| `reportDate` | 日報の日付（日本時間・`yyyy-MM-dd`） |
| `reportType` | `day`（昼用）／ `night`（夜用） |
| `body` | 日報本文 |
| `status` | `draft`（未送信）／ `sent`（本番ルームへ送信済み） |
| `generatedAt` | 生成日時 |
| `sentAt` | 送信日時（送信済みのときだけ入ります） |

## 4-2. 夜の日報の元になるスプレッドシート（必須）

夜の日報は、スプレッドシートの「日報」タブに書かれているものがそのまま本文になる。
GAS は読むだけで、文面を作らない。

| キー | 例 | 意味 |
| --- | --- | --- |
| `NIGHT_REPORT_SPREADSHEET_ID` | `1bBnz…HCEU` | スプレッドシートの ID（URL の `/d/` と `/edit` の間） |
| `NIGHT_REPORT_SHEET_NAME` | `日報` | 読むシート（タブ）の名前 |
| `NIGHT_REPORT_RANGE` | `B1:C24` | 読む範囲（列をまたいでもよい） |

読み直しはトリガー（18:25）が下書きを作るたびに毎回行われる。そのときのシートを読むので、
日々の内容は自動で入れ替わる。手で入れ直す必要はない。

**数字は計算しない。** 売上も進捗率もオンスケもシートの数式が出した値で、
表示されているとおりに読む。ここで計算し直すと、シートの式を直した日に日報だけ古い計算が
残り、二つの数字が食い違って、どちらが正しいか分からなくなる。

1 行の中は、左のセルから順に**そのままつなげて** 1 行にする。間に空白は入れない。
シートが B 列と C 列で 1 つの文を書いている（「2026年9月12日(土)」＋「の日報をお送りいたします。」）
ためで、ここで空白を足すと文が割れる。セルの間を空けたいときは、シート側でセルの中に空白を入れる。

桁を揃えている全角スペースはそのまま残す。落とすのは行末の空白と、範囲の末尾の空行だけ。
途中の空行は段落の区切りとして残す。

範囲の中身はそのまま本文になる。余分な空行も、書いてあれば載る。
範囲を決める前にシートを見ておくこと。

ただし `#REF!` などの数式のエラー表示だけは、行ごと飛ばす。計算が壊れている印であって、
相手に読ませる文ではない。範囲の途中に混じっていても、そこだけ避けて読む
（空行にすると、日報の中に不自然な隙間が残るため、行ごと落とす）。

読めないとき・範囲が空のときは、**下書きを作らずにエラーで止まる**。
空の日報や途中までの日報を下書きとして残すと、それに気づかないまま送ってしまうため。

なお、下書きを作ったあとにシートを更新しても、下書きは古いままになる。
書き換えてから「作り直す」を押すこと。

昼の日報はこの仕組みを使わない。今までどおりカレンダーの予定から組み立てる。

## 5. Google カレンダーの権限

初回実行時に承認画面が出るので、`yamamoto@aismiley.co.jp` で承認します。要求されるスコープは以下です。

| スコープ | 用途 |
|---|---|
| `calendar.readonly` | 予定と祝日の読み取り |
| `script.external_request` | Chatwork API への送信 |
| `script.scriptapp` | トリガーの作成 |

- 祝日カレンダーは、Google カレンダーで「日本の祝日」を購読していれば参照できます。
- 自分以外のカレンダーを対象にする場合は、そのカレンダーの閲覧権限が実行アカウントに必要です。
- 承認が `calendar.readonly` で通らない場合、または実行時に権限不足のエラーが出る場合は、
  `appsscript.json` のスコープを `https://www.googleapis.com/auth/calendar` に変更するか、
  `oauthScopes` のブロックごと削除してください（削除すると GAS が必要なスコープを自動で判定します）。

## 6. Chatwork API トークンの設定方法

1. Chatwork にログインし、右上のアカウント名 →［サービス連携］→［API Token］を開く。
2. パスワードを入力してトークンを表示し、コピーする。
3. Apps Script の［スクリプト プロパティ］に `CHATWORK_API_TOKEN` として貼り付ける。
4. 本番ルーム（`122205264`）に、そのトークンの持ち主が参加していることを確認する
   （参加していないと 403 になります）。

トークンは HTTP ヘッダー `x-chatworktoken` で送信します（URL には含めません）。

## 7. トリガーの設定方法

エディタで `setupTriggers` を 1 回実行してください。以下の 2 つが作成されます。

| 関数 | 実行タイミング |
|---|---|
| `runDayReport` | 毎日 12:55 頃（下書きを作る。送信はしない） |
| `runNightReport` | 毎日 18:25 頃（下書きを作る。送信はしない） |

- 時刻を変えたい場合は `config.gs` の `DAY_REPORT_HOUR` / `DAY_REPORT_MINUTE` /
  `NIGHT_REPORT_HOUR` / `NIGHT_REPORT_MINUTE` を書き換えて `setupTriggers()` を再実行します。
- 送信予定時刻（13:00 / 18:30）の 5 分前に下書きを用意する設定です。
- **GAS のトリガーは指定時刻ちょうどには動きません**（前後 15 分ほどぶれます）。
  送信のタイミングは §8 の手動送信で自分で決められるため、この揺れは投稿時刻に影響しません。
- 何度実行しても重複しません（同じ関数の既存トリガーを作り直します）。
- **土日祝でもトリガーは削除・停止しないでください。** 実行時に営業日を判定してスキップします。
  （金曜に止めて月曜も止まったまま、という事故を防ぐための設計です）

手動で作る場合は［トリガー］画面で、イベントのソース「時間主導型」→「日付ベースのタイマー」→
「午後 12 時〜1 時」/「午後 6 時〜7 時」を選び、関数に `runDayReport` / `runNightReport` を指定します。

## 8. 毎日の使い方（確認してから送る）

| 手順 | 操作 | 起きること |
|---|---|---|
| 1 | （自動）12:55 / 18:25 頃にトリガーが動く | 日報が作られ、GAS 内に下書きとして保存される。**Chatwork へは送られない** |
| 2 | `showDayDraft()` / `showNightDraft()` を実行 | 下書きの本文と状態がログに出る（下書きが無ければその場で作る） |
| 3 | 内容を確認する | そのままでよければ手順 4 へ |
| 4 | `sendDayDraft()` / `sendNightDraft()` を実行 | 本番ルーム（`122205264`）へ投稿され、状態が `sent` になる |

- **所感を書き足したい場合**は、手順 2 で表示された本文をコピーし、Chatwork の入力欄へ
  貼り付けてから所感を書いて自分で送信してください。
  その場合、`sendDayDraft()` / `sendNightDraft()` は実行しないでください（二重投稿になります）。
- 送信済みの日に再度 `sendDayDraft()` を実行しても、二重には投稿されません。
- トリガーを待たずに、いつでも手順 2 から始められます（その場で下書きが作られます）。
- 同じ日にトリガーがもう一度動いても、内容が変わっていなければ下書きはそのままです。
  カレンダーの予定が変わっていた場合は、新しい内容で保存し直されます。

## 9. 実行ボタンから選べる関数

Apps Script の実行ボタンは引数を渡せないため、日付などを受け取る関数を選ぶとエラーになります。
そこで、**実行メニューに出るのは次の 10 個だけ**にしてあります（名前の末尾が `_` の関数は
Apps Script がメニューに表示しません）。

| 関数 | すること | Chatwork |
|---|---|---|
| `runAllTests` | 17 件のテストをまとめて実行 | 送信しない |
| `showDayDraft` / `showNightDraft` | 下書きをログに表示（無ければその場で作る） | 送信しない |
| `sendDayDraft` / `sendNightDraft` | 確認した下書きを本番ルームへ投稿 | **送信する** |
| `runDayReport` / `runNightReport` | 下書きを作り直す（トリガーが実行するもの） | 送信しない |
| `testDayReport` / `testNightReport` | 本文だけをログに表示（下書きも保存しない） | 送信しない |
| `setupTriggers` | 12:55 / 18:25 のトリガーを作る | 送信しない |

## 10. テスト方法

| 関数 | 内容 |
|---|---|
| `runAllTests()` | 25 件のテストケース（昼・夜の本文、土日祝、二重投稿防止、シートの読み取りなど）をまとめて実行 |
| `testDayReport()` | 当日の昼の日報本文をログに出力（投稿しない） |
| `testNightReport()` | 当日の夜の日報本文をログに出力（投稿しない） |
| `testDayReportForDate_('2026-09-11')` | 日付を指定して昼の本文を確認（投稿しない） |
| `testNightReportForDate_('2026-09-11')` | 日付を指定して夜の本文を確認（投稿しない） |

日付指定の関数はエディタの実行ボタンからは引数を渡せないため、
一時的な関数（例: `function tmp() { testNightReportForDate_('2026-09-11'); }`）を作って実行してください。

結果は［実行数］または `Ctrl + Enter`（実行ログ）で確認できます。
**テスト関数は Chatwork へ一切送信しません。**

## 11. 運用開始の手順

1. Script Properties に `CHATWORK_API_TOKEN` と `CHATWORK_ROOM_ID` を設定する。
2. `testDayReport()` を実行し、承認を済ませたうえで本文を確認する（**どこにも送信されません**）。
3. `runAllTests()` を実行し、すべて成功することを確認する。
4. `testNightReport()` を実行し、スプレッドシートの内容がそのまま出ることを確認する。
5. `runDayReport()` を手動で 1 回実行し、**下書きが保存され、Chatwork へは送信されない**ことを
   ログで確認する。
6. `showDayDraft()` で下書きの内容を確認する。
7. 問題なければ `sendDayDraft()` を実行し、本番ルームへ投稿されることを確認する。
8. `setupTriggers()` を実行してトリガーを作成する。
9. 翌営業日の 12:55 / 18:25 頃に下書きが作られていることを確認し、内容を見てから手動で送る。

## 12. 休業日の判定ルール

土曜・日曜に加えて、祝日カレンダーの予定がある日を休業日として扱います。
ただし Google の「日本の祝日」カレンダーは、**祝日と行事の両方**を含んでいます。

| 予定の説明の 1 行目 | 扱い | 例 |
|---|---|---|
| `祝日` | 休業日（投稿しない） | 元日 / 成人の日 / 憲法記念日 振替休日 / 国民の休日 / 秋分の日 |
| `祭日` | **営業日（通常どおり投稿する）** | 節分 / 七夕 / 母の日 / 銀行休業日(1/2・1/3) |

行事まで休業日にしてしまうと、節分（火）や七夕（火）に日報が出なくなるため、
説明の 1 行目で種別を判定しています。判定に使う種別名は `config.gs` の
`HOLIDAY_CALENDAR_NON_HOLIDAY_LABELS` で変更できます。
説明が空・不明な種別の場合は、祝日に誤投稿しないよう安全側（休業日）に倒します。

### 年末年始など、会社独自の休みに投稿を止めたい場合

1/2・1/3（銀行休業日）は国民の祝日ではないため、この仕組みでは**営業日**として投稿されます。
会社の休みに合わせて止めたい日がある場合は、その日の送信済みフラグを
Script Properties へ**あらかじめ手で登録**してください（新しい設定は不要です）。

| キー | 値 |
|---|---|
| `20260102_day` | `sent` |
| `20260102_night` | `sent` |

こうしておくと、その日はトリガーが動いても投稿されません。

## 13. 既知の制約

- **トリガーの実行時刻は厳密ではありません。** GAS の時間主導型トリガーは指定時刻の前後
  15 分ほどぶれます（12:55 / 18:25 は目安です）。投稿時刻は手動送信で自分で決められるため、
  この揺れが Chatwork の投稿時刻に影響することはありません。
- **下書きの確認には Apps Script エディタが必要です。** 現時点では下書きを見る手段が
  `showDayDraft()` / `showNightDraft()` のログだけです（AI 業務プラットフォームからの
  確認・編集は今後の対応で、今回は未実装です）。
- **コピーして本番へ貼った場合、GAS は「送信済み」と分かりません。**
  その日に `sendDayDraft()` を実行すると二重投稿になります（併用しないでください）。
- **下書きは日付ごとに増え続けます。** Script Properties の容量的には長期間問題ありませんが、
  不要になったら `draft_20260911_day` などのキーを削除できます。
- **終日イベントは対象外です。** 時刻付きの予定のみを日報に載せます。
  含めたい場合は `config.gs` の `INCLUDE_ALL_DAY_EVENTS` を `true` にしてください
  （終日イベントは開始時刻が 00:00 のため AM 扱いになります）。
- **前日から続く予定は当日分に含めません。** 開始日が当日の予定のみを対象とします。
- **祝日カレンダーに依存します。** 祝日カレンダーへアクセスできない場合は、
  誤って祝日に投稿しないようエラーで停止します（投稿はされません）。
  祝日と行事の区別は Google 側の説明文（`祝日` / `祭日`）に依存しているため、
  Google がこの表記を変えた場合は §12 の設定を見直す必要があります。
- **会社独自の休み（年末年始・夏季休暇など）は判定できません。** §12 の手順で個別に止めてください。
- **送信済みフラグは日付ごとに増え続けます。** 1 日 2 件で、Script Properties の容量的には
  長期間問題ありませんが、再送信したい場合は該当キー（`20260911_day` など）を手動で削除します。
- **投稿後にフラグ記録が失敗した場合**、同日に再実行すると二重投稿になり得ます
  （発生時はログにエラーが残ります）。
- **所感は自動生成しません。** 下書きをコピーして Chatwork 上で書き足すか、投稿後に追記する運用です。
- **カレンダーのタイトルをそのまま使います。** 要約・言い換えはしません。

## 14. AI Work（業務プラットフォーム）から使う

プラットフォームの［日報］画面から、下書きの確認・編集・送信ができます。
スプレッドシートを開かなくても、同じことがブラウザ上で完結します。

```
ブラウザ（/daily-report）
   ↓
Next.js のサーバー（/api/daily-report）   ← 合言葉はここに置く
   ↓ POST
GAS のウェブアプリ（doPost）
   ↓
「日報」シート ／ Chatwork
```

Chatwork のトークンは GAS の中から出ません。合言葉もサーバー側にしか無いので、
ブラウザの開発者ツールから見えることはありません。

### 設定手順

1. Apps Script の［スクリプト プロパティ］に `API_SHARED_SECRET` を追加し、
   推測されにくい文字列を設定する（パスワード生成器などで作った 32 文字程度）。
2. ［デプロイ］→［新しいデプロイ］→ 種類は **ウェブアプリ**。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（合言葉が合わないリクエストは弾きます）
3. 表示された **ウェブアプリの URL**（`…/exec` で終わるもの）を控える。
4. Vercel の環境変数に次の 2 つを設定する。

   | 変数 | 値 |
   |---|---|
   | `DAILY_REPORT_GAS_URL` | 手順 3 の URL |
   | `DAILY_REPORT_SECRET` | 手順 1 の合言葉 |

5. 再デプロイすると、サイドナビに［日報］が出ます。

> コードを更新したときは、［デプロイ］→［デプロイを管理］→ 鉛筆マーク →
> バージョンを「新バージョン」にして更新してください。URL は変わりません。

### やり取りの内容

| 操作 | 送るもの | すること |
|---|---|---|
| `drafts` | — | 今日の昼・夜の状態を返す（何も書き換えない） |
| `rebuild` | `reportType` | 最新のカレンダーで下書きを作り直す |
| `save` | `reportType`, `body` | シートの本文を書き換える |
| `send` | `reportType` | Chatwork の本番ルームへ送る |

どの操作でも、終わったあとの状態をまとめて返します。
送信済みの日報は、書き換えも作り直しも送信もできません。
