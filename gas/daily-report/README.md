# 日報自動生成システム（Google Apps Script）

Google カレンダーの予定から日報を生成し、Chatwork の指定ルームへ自動投稿する GAS プロジェクトです。
リポジトリ内の Next.js アプリとは独立しており、単体で動作します。

- 昼（12:50 頃）: 当日 AM を「業務報告」、当日 PM を「業務予定」として投稿
- 夜（18:20 頃）: 当日 PM を「業務報告」、**次営業日**の AM / PM を「業務予定」として投稿
- 土日祝は投稿しない（トリガーは止めない）
- LLM は使用しない。カレンダーのタイトルをそのまま整形するだけ

## 1. ファイル構成

| ファイル | 責務 |
|---|---|
| `main.gs` | エントリポイント（自動実行・手動実行・テスト・トリガー設定） |
| `config.gs` | 設定の取得（Script Properties・定数・タイムゾーン確認） |
| `date.gs` | 日本時間前提の日付ユーティリティ（曜日・日付キー・日付表示） |
| `businessDay.gs` | 営業日判定・次営業日の算出（土日＋祝日カレンダー参照） |
| `calendar.gs` | Google カレンダーからの予定取得・AM / PM 分類・開始時刻順の並び替え |
| `report.gs` | 日報本文の生成（昼・夜） |
| `chatwork.gs` | Chatwork API への投稿 |
| `lock.gs` | 二重実行（LockService）・二重投稿（送信済みフラグ）の防止 |
| `test.gs` | テスト（`runAllTests`）。Chatwork へは送信しない |
| `appsscript.json` | プロジェクト設定（タイムゾーン・OAuth スコープ） |

## 2. 実装した機能

| 機能 | 対応する関数 |
|---|---|
| カレンダーから予定を取得 | `getCalendarEvents(date)` |
| AM / PM の分類（開始時刻基準・AM は 00:00:00–11:59:59） | `getMorningEvents(date)` / `getAfternoonEvents(date)` |
| 昼の日報の生成 | `generateDayReport(date)` / `buildDayReportBody(am, pm)` |
| 夜の日報の生成 | `generateNightReport(date)` / `buildNightReportBody(date, todayPm, nextAm, nextPm)` |
| 土日祝の判定 | `isBusinessDay(date)` |
| 次営業日の算出 | `getNextBusinessDay(date)` |
| Chatwork への投稿 | `sendToChatwork(message)` |
| 自動実行トリガーの設定 | `setupTriggers()` |
| 二重投稿の防止 | `hasAlreadySent(key)` / `markAsSent(key)` |
| 同時実行の防止 | `runExclusively_(task)`（`LockService.getScriptLock()`） |
| 手動実行 | `runDayReport()` / `runNightReport()` |
| テストモード（投稿しない） | `testDayReport()` / `testNightReport()` / `runAllTests()` |

### 日報のフォーマット

昼:

```
【昼用】
---業務報告---
AM
■予定1
■予定2
 
---業務予定---
PM
■予定3
■予定4
```

（`---業務予定---` の直前は半角スペース 1 つだけの行です）

夜:

```
【夜用】
お疲れ様です。山本です。
2026年9月11日(金)の日報をお送りいたします。
---業務報告---
PM
■当日PMの予定
---業務予定---
AM
■次営業日AMの予定
PM
■次営業日PMの予定
---所感---
```

- 夜の「業務報告」は**当日 PM のみ**。当日 AM は入りません。
- 「所感」は空欄のままです（自動生成しません）。
- 予定が無い時間帯でも `AM` / `PM` の見出しは残し、「予定なし」等は入れません。
- カレンダーのタイトルに既に `■` が付いている場合、二重には付きません。

## 3. Google Apps Script 側で必要な設定

1. 会社の Google アカウント（`yamamoto@aismiley.co.jp`）でログインする。
2. 新しい Apps Script プロジェクトを作成する。
3. `*.gs` の各ファイルを同名で作成し、内容を貼り付ける。
4. ［プロジェクトの設定］→［全般設定］で **タイムゾーンを `Asia/Tokyo`** にする。
   （ずれていると実行時にエラーになります）
5. `appsscript.json` を反映する場合は、［プロジェクトの設定］で
   「`appsscript.json` マニフェスト ファイルをエディタで表示する」を有効にしてから貼り付ける。

> clasp を使う場合は、このディレクトリをそのまま `clasp push` の対象にできます
> （`.clasp.json` は各自のローカルで作成してください。リポジトリには含めません）。

## 4. Script Properties へ設定する値

［プロジェクトの設定］→［スクリプト プロパティ］で設定します。

| キー | 必須 | 内容 |
|---|---|---|
| `CHATWORK_API_TOKEN` | 必須 | Chatwork の API トークン |
| `CHATWORK_ROOM_ID` | 必須 | 投稿先ルーム ID（今回は `122205264`） |
| `HOLIDAY_CALENDAR_ID` | 任意 | 祝日カレンダー ID。未設定なら `ja.japanese#holiday@group.v.calendar.google.com`（→ §11） |
| `TARGET_CALENDAR_ID` | 任意 | 予定を取得するカレンダー ID。未設定なら実行アカウントのデフォルトカレンダー |

**API トークンはコード・README・Git に絶対に書かないでください。** 設定するのは Script Properties だけです。

なお、送信済み管理用に `20260911_day` / `20260911_night` のようなキーも同じ Script Properties へ
自動で追加されます（値は `sent`）。手動で消すと、その日の日報が再送信できるようになります。

## 5. Google カレンダーの権限

初回実行時に承認画面が出るので、`yamamoto@aismiley.co.jp` で承認します。要求されるスコープは以下です。

| スコープ | 用途 |
|---|---|
| `calendar.readonly` | 予定と祝日の読み取り |
| `script.external_request` | Chatwork API への送信 |
| `script.scriptapp` | トリガーの作成 |

- 祝日カレンダーは、Google カレンダーで「日本の祝日」を購読していれば参照できます。
- 自分以外のカレンダーを対象にする場合は、そのカレンダーの閲覧権限が実行アカウントに必要です。
- 承認が `calendar.readonly` で通らない場合、または実行時に権限不足のエラーが出る場合は、
  `appsscript.json` のスコープを `https://www.googleapis.com/auth/calendar` に変更するか、
  `oauthScopes` のブロックごと削除してください（削除すると GAS が必要なスコープを自動で判定します）。

## 6. Chatwork API トークンの設定方法

1. Chatwork にログインし、右上のアカウント名 →［サービス連携］→［API Token］を開く。
2. パスワードを入力してトークンを表示し、コピーする。
3. Apps Script の［スクリプト プロパティ］に `CHATWORK_API_TOKEN` として貼り付ける。
4. 投稿先ルーム（`122205264`）に、そのトークンの持ち主が参加していることを確認する。

トークンは HTTP ヘッダー `x-chatworktoken` で送信します（URL には含めません）。

## 7. トリガーの設定方法

エディタで `setupTriggers` を 1 回実行してください。以下の 2 つが作成されます。

| 関数 | 実行タイミング |
|---|---|
| `runDayReport` | 毎日 12:50 頃 |
| `runNightReport` | 毎日 18:20 頃 |

- 何度実行しても重複しません（同じ関数の既存トリガーを作り直します）。
- **土日祝でもトリガーは削除・停止しないでください。** 実行時に営業日を判定してスキップします。
  （金曜に止めて月曜も止まったまま、という事故を防ぐための設計です）

手動で作る場合は［トリガー］画面で、イベントのソース「時間主導型」→「日付ベースのタイマー」→
「午後 12 時〜1 時」/「午後 6 時〜7 時」を選び、関数に `runDayReport` / `runNightReport` を指定します。

## 8. テスト方法

| 関数 | 内容 |
|---|---|
| `runAllTests()` | 仕様のテストケース（昼・夜の本文、次営業日、土日祝、二重投稿防止など）をまとめて実行 |
| `testDayReport()` | 当日の昼の日報本文をログに出力（投稿しない） |
| `testNightReport()` | 当日の夜の日報本文をログに出力（投稿しない） |
| `testDayReportForDate('2026-09-11')` | 日付を指定して昼の本文を確認（投稿しない） |
| `testNightReportForDate('2026-09-11')` | 日付を指定して夜の本文を確認（投稿しない） |

日付指定の関数はエディタの実行ボタンからは引数を渡せないため、
一時的な関数（例: `function tmp() { testNightReportForDate('2026-09-11'); }`）を作って実行してください。

結果は［実行数］または `Ctrl + Enter`（実行ログ）で確認できます。
**テスト関数は Chatwork へ一切送信しません。**

## 9. 本番運用の開始手順

1. Script Properties に `CHATWORK_API_TOKEN` と `CHATWORK_ROOM_ID` を設定する。
2. `testDayReport()` を実行し、承認を済ませたうえで本文を確認する。
3. `runAllTests()` を実行し、すべて成功することを確認する。
4. `testNightReport()` を実行し、次営業日の予定が正しく入ることを確認する。
5. `runDayReport()` を手動で 1 回実行し、Chatwork に投稿されることを確認する。
   （この時点で当日分は送信済みになり、当日の自動実行では再投稿されません）
6. `setupTriggers()` を実行してトリガーを作成する。
7. 翌営業日の 12:50 / 18:20 に投稿されることを確認する。

## 10. 休業日の判定ルール

土曜・日曜に加えて、祝日カレンダーの予定がある日を休業日として扱います。
ただし Google の「日本の祝日」カレンダーは、**祝日と行事の両方**を含んでいます。

| 予定の説明の 1 行目 | 扱い | 例 |
|---|---|---|
| `祝日` | 休業日（投稿しない） | 元日 / 成人の日 / 憲法記念日 振替休日 / 国民の休日 / 秋分の日 |
| `祭日` | **営業日（通常どおり投稿する）** | 節分 / 七夕 / 母の日 / 銀行休業日(1/2・1/3) |

行事まで休業日にしてしまうと、節分（火）や七夕（火）に日報が出なくなるため、
説明の 1 行目で種別を判定しています。判定に使う種別名は `config.gs` の
`HOLIDAY_CALENDAR_NON_HOLIDAY_LABELS` で変更できます。
説明が空・不明な種別の場合は、祝日に誤投稿しないよう安全側（休業日）に倒します。

### 年末年始など、会社独自の休みに投稿を止めたい場合

1/2・1/3（銀行休業日）は国民の祝日ではないため、この仕組みでは**営業日**として投稿されます。
会社の休みに合わせて止めたい日がある場合は、その日の送信済みフラグを
Script Properties へ**あらかじめ手で登録**してください（新しい設定は不要です）。

| キー | 値 |
|---|---|
| `20260102_day` | `sent` |
| `20260102_night` | `sent` |

こうしておくと、その日はトリガーが動いても投稿されません。

## 11. 既知の制約

- **実行時刻は厳密ではありません。** GAS の時間主導型トリガーは指定時刻の前後で実行されます
  （12:50 / 18:20 は目安です）。
- **終日イベントは対象外です。** 時刻付きの予定のみを日報に載せます。
  含めたい場合は `config.gs` の `INCLUDE_ALL_DAY_EVENTS` を `true` にしてください
  （終日イベントは開始時刻が 00:00 のため AM 扱いになります）。
- **前日から続く予定は当日分に含めません。** 開始日が当日の予定のみを対象とします。
- **祝日カレンダーに依存します。** 祝日カレンダーへアクセスできない場合は、
  誤って祝日に投稿しないようエラーで停止します（投稿はされません）。
  祝日と行事の区別は Google 側の説明文（`祝日` / `祭日`）に依存しているため、
  Google がこの表記を変えた場合は §10 の設定を見直す必要があります。
- **会社独自の休み（年末年始・夏季休暇など）は判定できません。** §10 の手順で個別に止めてください。
- **送信済みフラグは日付ごとに増え続けます。** 1 日 2 件で、Script Properties の容量的には
  長期間問題ありませんが、再送信したい場合は該当キー（`20260911_day` など）を手動で削除します。
- **投稿後にフラグ記録が失敗した場合**、同日に再実行すると二重投稿になり得ます
  （発生時はログにエラーが残ります）。
- **所感は自動生成しません。** 投稿後に Chatwork 上で追記する運用です。
- **カレンダーのタイトルをそのまま使います。** 要約・言い換えはしません。
